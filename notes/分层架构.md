# 项目分层架构

> 项目：`go-http-service`  
> 主题：为什么要做分层架构，以及如何在 Go Web 项目中实现分层

---

## 一、什么是分层架构

分层架构（Layered Architecture）是把代码按照职责划分到不同的层级中，每层只和相邻的层级交互。

当前项目把所有代码都放在 `cmd/server/main.go` 中。当接口增多、业务复杂后，会出现以下问题：

- 代码大量堆积在 `main.go`
- 业务逻辑和 HTTP 处理混在一起
- 数据库操作直接写在 handler 里
- 难以单元测试
- 难以多人协作

分层架构就是解决这些问题的。

---

## 二、常见的四层结构

对于中小型 Go Web 项目，推荐采用以下四层结构：

```
HTTP Handler（入口层）
        ↓
   Service（业务逻辑层）
        ↓
 Repository（数据访问层）
        ↓
   Database（数据存储层）
```

| 层级 | 英文 | 职责 | 示例 |
|------|------|------|------|
| 入口层 | Handler | 接收 HTTP 请求，解析参数，调用 Service，返回响应 | `user_handler.go` |
| 业务层 | Service | 处理业务规则、流程编排、权限判断 | `user_service.go` |
| 数据层 | Repository | 负责和数据库交互，执行 CRUD | `user_repository.go` |
| 模型层 | Model | 定义数据结构（结构体、常量） | `user.go` |

---

## 三、为什么要分层

### 1. 职责清晰

每个文件只负责一件事：

- Handler：只管接收 HTTP 请求
- Service：只管业务规则
- Repository：只管读写数据库

### 2. 便于测试

业务逻辑和数据访问分离后，可以用 mock 替换真实数据库，单独测试 Service 层。

### 3. 便于替换实现

比如今天用 PostgreSQL，明天想换成 MySQL，只要改 Repository 层即可，Service 和 Handler 不需要动。

### 4. 避免代码重复

多个 Handler 可能调用同一个 Service 函数，不用重复写业务代码。

## 四、应用到当前项目

当前项目的 `cmd/server/main.go` 里直接处理请求：

```go
func healthHandler(c *gin.Context) {
    c.JSON(http.StatusOK, NewHealthResponse())
}
```

对于 `/api/health` 这种简单接口，直接返回就行，没必要分层。

但当实现 `/api/users` 这种接口时，就需要分层：

```text
GET  /api/users/:id
      ↓
userHandler.GetByID
      ↓
userService.GetByID
      ↓
userRepository.FindByID
      ↓
PostgreSQL
```

## 五、推荐目录结构

实现分层后，项目目录会变成这样：

```
go-http-service/
├── cmd/
│   └── server/
│       └── main.go              # 只负责启动路由
├── internal/
│   ├── handler/                 # HTTP Handler
│   │   ├── health_handler.go
│   │   ├── user_handler.go
│   │   └── router.go            # 路由注册
│   ├── service/                 # 业务逻辑
│   │   └── user_service.go
│   ├── repository/              # 数据访问
│   │   └── user_repository.go
│   ├── model/                   # 数据结构
│   │   └── user.go
│   └── config/                  # 配置
│       └── config.go
├── go.mod
├── go.sum
├── README.md
└── notes/
```

## 六、各层示例

### 6.1 Model 层：定义数据结构

```go
package model

type User struct {
    ID       int64  `json:"id"`
    Username string `json:"username"`
    Email    string `json:"email"`
    Password string `json:"-"`  // 不返回给前端
}
```

### 6.2 Repository 层：访问数据库

```go
package repository

import (
    "database/sql"
    "go-http-service/internal/model"
)

type UserRepository struct {
    db *sql.DB
}

func NewUserRepository(db *sql.DB) *UserRepository {
    return &UserRepository{db: db}
}

func (r *UserRepository) FindByID(id int64) (*model.User, error) {
    row := r.db.QueryRow("SELECT id, username, email FROM users WHERE id = $1", id)
    user := &model.User{}
    err := row.Scan(&user.ID, &user.Username, &user.Email)
    return user, err
}
```

### 6.3 Service 层：处理业务逻辑

```go
package service

import (
    "errors"
    "go-http-service/internal/model"
    "go-http-service/internal/repository"
)

type UserService struct {
    repo *repository.UserRepository
}

func NewUserService(repo *repository.UserRepository) *UserService {
    return &UserService{repo: repo}
}

func (s *UserService) GetByID(id int64) (*model.User, error) {
    if id <= 0 {
        return nil, errors.New("invalid user id")
    }
    return s.repo.FindByID(id)
}
```

### 6.4 Handler 层：处理 HTTP 请求

```go
package handler

import (
    "net/http"
    "strconv"

    "github.com/gin-gonic/gin"
    "go-http-service/internal/service"
)

type UserHandler struct {
    svc *service.UserService
}

func NewUserHandler(svc *service.UserService) *UserHandler {
    return &UserHandler{svc: svc}
}

func (h *UserHandler) GetByID(c *gin.Context) {
    idParam := c.Param("id")
    id, err := strconv.ParseInt(idParam, 10, 64)
    if err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": "invalid id"})
        return
    }

    user, err := h.svc.GetByID(id)
    if err != nil {
        c.JSON(http.StatusNotFound, gin.H{"error": "user not found"})
        return
    }

    c.JSON(http.StatusOK, user)
}
```

### 6.5 main.go 只负责启动

```go
func main() {
    db, err := sql.Open("postgres", "...")
    if err != nil {
        log.Fatal(err)
    }

    userRepo := repository.NewUserRepository(db)
    userSvc := service.NewUserService(userRepo)
    userHandler := handler.NewUserHandler(userSvc)

    r := gin.Default()
    r.GET("/api/users/:id", userHandler.GetByID)

    r.Run(":8080")
}
```

## 七、分层的注意事项

1. **不要过度分层**：简单 CRUD 可能不需要完整的服务层，但要根据项目规模判断。
2. **Handler 不要直接调用 Repository**：必须通过 Service，保持依赖方向一致。
3. **错误处理要分层返回**：每层返回自己职责范围内的错误。
4. **不要循环依赖**：Handler → Service → Repository，不能反向依赖。

---

## 八、什么时候引入分层

建议在做以下功能时引入分层：

- 用户系统（注册、登录）
- 博客文章 CRUD
- 涉及数据库操作的接口

也就是说，**做完 `/api/info` 和 `/api/echo` 之后，下一步做数据库连接和用户系统时，就应该开始分层**。
