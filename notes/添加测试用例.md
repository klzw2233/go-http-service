# 添加测试用例

> 项目：`go-http-service`  
> 主题：如何为 Go Web 服务添加测试用例

---

## 一、为什么要写测试

当前项目我们手动启动服务，然后用 curl 测试接口。这种方式有两个问题：

1. **效率低**：每次改代码都要手动启动、手动请求
2. **容易遗漏**：只测了正常情况，没测错误情况

测试用例可以自动验证代码：

- 改一行代码后，跑一遍测试就知道有没有坏
- 保证新功能不影响旧功能
- 防止回归 bug
- 为重构提供信心

---

## 二、Go 测试基础

Go 使用内置的 `testing` 包，测试文件以 `_test.go` 结尾。

例如：

```go
package main

import "testing"

func TestAdd(t *testing.T) {
    result := add(1, 2)
    if result != 3 {
        t.Errorf("expected 3, got %d", result)
    }
}
```

运行测试：

```bash
go test ./...
```

## 三、HTTP Handler 测试

对于 Web 项目，最常见的测试是 **HTTP Handler 测试**。

Go 的 `net/http/httptest` 包提供了测试 HTTP handler 的工具，不需要真的启动一个服务监听端口。

### 基本流程

```go
package main

import (
    "net/http"
    "net/http/httptest"
    "testing"

    "github.com/gin-gonic/gin"
    "github.com/stretchr/testify/assert"
)

func TestHealthHandler(t *testing.T) {
    // 1. 设置 Gin 为测试模式
    gin.SetMode(gin.TestMode)

    // 2. 创建路由
    r := setupRouter()

    // 3. 构造请求
    req := httptest.NewRequest(http.MethodGet, "/api/health", nil)
    resp := httptest.NewRecorder()

    // 4. 发送请求
    r.ServeHTTP(resp, req)

    // 5. 验证结果
    assert.Equal(t, http.StatusOK, resp.Code)
    assert.Contains(t, resp.Body.String(), `"status":"ok"`)
}
```

### 关键点说明

| 组件 | 作用 |
|------|------|
| `httptest.NewRequest` | 构造一个假的 HTTP 请求 |
| `httptest.NewRecorder` | 记录 handler 返回的响应 |
| `r.ServeHTTP` | 把请求传给 Gin 路由处理 |
| `resp.Code` | 响应状态码 |
| `resp.Body.String()` | 响应体内容 |

## 四、当前项目的测试示例

为现有三个接口各写一个测试：

### 4.1 `GET /api/health` 测试

```go
func TestHealthHandler(t *testing.T) {
    gin.SetMode(gin.TestMode)
    r := setupRouter()

    req := httptest.NewRequest(http.MethodGet, "/api/health", nil)
    resp := httptest.NewRecorder()

    r.ServeHTTP(resp, req)

    assert.Equal(t, http.StatusOK, resp.Code)
    assert.Contains(t, resp.Body.String(), "ok")
}
```

### 4.2 `GET /api/info` 测试

```go
func TestInfoHandler(t *testing.T) {
    gin.SetMode(gin.TestMode)
    r := setupRouter()

    req := httptest.NewRequest(http.MethodGet, "/api/info", nil)
    resp := httptest.NewRecorder()

    r.ServeHTTP(resp, req)

    assert.Equal(t, http.StatusOK, resp.Code)
    assert.Contains(t, resp.Body.String(), "go-http-service")
}
```

### 4.3 `POST /api/echo` 测试

```go
func TestEchoHandler(t *testing.T) {
    gin.SetMode(gin.TestMode)
    r := setupRouter()

    body := `{"message":"hello"}`
    req := httptest.NewRequest(http.MethodPost, "/api/echo", strings.NewReader(body))
    req.Header.Set("Content-Type", "application/json")

    resp := httptest.NewRecorder()
    r.ServeHTTP(resp, req)

    assert.Equal(t, http.StatusOK, resp.Code)
    assert.Contains(t, resp.Body.String(), "hello")
}
```

### 4.4 `POST /api/echo` 错误情况测试

```go
func TestEchoHandler_BadRequest(t *testing.T) {
    gin.SetMode(gin.TestMode)
    r := setupRouter()

    body := `{}`  // 缺少 message 字段
    req := httptest.NewRequest(http.MethodPost, "/api/echo", strings.NewReader(body))
    req.Header.Set("Content-Type", "application/json")

    resp := httptest.NewRecorder()
    r.ServeHTTP(resp, req)

    assert.Equal(t, http.StatusBadRequest, resp.Code)
}
```

## 五、测试文件放在哪里

推荐两种组织方式：

### 方式一：与源码同目录

```
cmd/server/
├── main.go
├── health_handler.go    // 可选：拆分后
└── main_test.go         // 测试文件
```

适合小型项目。

### 方式二：放到独立的测试目录

```go-http-service/
├── internal/
│   └── handler/
│       ├── health_handler.go
│       └── health_handler_test.go
```

适合分层后的中大型项目。

## 六、常用的测试库

### 1. `testify`

最常用的测试断言库：

```bash
go get github.com/stretchr/testify
```

```go
assert.Equal(t, expected, actual)
assert.Contains(t, "hello world", "hello")
assert.NoError(t, err)
assert.Error(t, err)
```

### 2. `gin` 测试模式

测试前一定要设置：

```go
gin.SetMode(gin.TestMode)
```

这可以关闭 Gin 的日志输出，让测试结果更干净。

## 七、测试的分类

| 类型 | 范围 | 速度 | 示例 |
|------|------|------|------|
| 单元测试 | 单个函数 | 快 | `TestHealthHandler` |
| 集成测试 | 多个模块协作 | 中 | handler + service + database |
| E2E 测试 | 完整请求链路 | 慢 | 启动服务 + 发送真实 HTTP 请求 |

对于当前项目，先写 **Handler 单元测试** 就够了。

go test ./... -run TestEcho

## 九、什么时候写测试

建议养成**先写测试，再写实现**的习惯，也就是 TDD（测试驱动开发）。但对于初学者来说，可以先写实现，再补测试。

最低要求：

- 每增加一个新接口，至少写一个正常情况的测试
- 关键接口要补充错误情况测试
- 重构代码前，先确保有测试覆盖
